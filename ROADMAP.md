## Known limits

- A calendar reads the first 1,000 rows of the six weeks it shows; its days still count every row. A map shows the first 5,000 rows that have a place, and says so. A grouped grid shows its first 2,000 groups.
- Imports, copies, and base snapshots stop at 100,000 rows (rows 82, 83), and so does the direct download of a view. An export job stops at the ceiling the operator sets (`EXPORT_MAX_ROWS`, 1,000,000 by default); it reads page after page by offset, so its last pages take longer. Export and snapshot files are kept for 24 hours.
- An interrupted job is not retried: its author starts it again (row 47).
- A field can require a value in AnyGridDB's own tables only (a client's database says itself what it requires), and not on a checkbox, a person, a file, or a link. Rows already empty when it becomes required stay so until that field is changed.
- A view saved while one of its fields is in the trash keeps that field's place and settings, but not its conditions inside a nested filter group, a colour rule, or a form field's condition.
- A base snapshot names people by email: a user cell keeps the people who are members of the new base. Roles given by groups stay behind.
- A collaborator with field or row rules finds in the row trash only the rows they deleted, named by their primary field when they may see it; on a client's table they have no row trash.
- Rows deleted before this release's many-to-many restore fix come back without those links.
- A SAML provider that sends only transient or address NameIDs matches accounts by address: it must verify them. OIDC, and SAML with a persistent NameID, bind the account to the provider's subject.
- The map view draws points on a plain SVG projection, without tiles (row 86).
- A synced table is as old as its last refresh, is read-only, stops at a million rows, and links to a table read live show empty.
- A locked client row is protected from AnyGridDB's writes only: a change another application makes is detected (within five minutes, seconds on a watched table) and told, not refused. Its seal covers every stored column, so a row put back still differs by its `updated_at`.
- On SQL Server a page is one query: a table with very many complex computed fields can exceed what SQL Server compiles, and AnyGridDB says so. There, MD5, SHA256, and SHA512 read texts of up to 100,000 characters, and JSON_EXTRACT reads a text value of up to 4,000.
- On Oracle an empty text is NULL, so a blank text and lists built from it read as nothing; `NUMBER` keeps no scale (`7.50` reads `7.5`); `DATE` reads as a day; regular expressions are refused, as on SQL Server. Only Oracle 23ai is tested; 19c is the floor (docs/sources.md).
- Regular expressions are a portable subset, written in the formula: `\d`, `\w`, and `\s` are ASCII, and back-references and lookbehinds are refused. SQL Server reads none before 2025, so there they are refused.
- JSON_EXTRACT needs PostgreSQL 16 or later, where a text that is not JSON can be told apart without failing the read. On MySQL it reads JSON numbers as doubles, and the field says so.
- The opt-in release check stays silent until an administrator turns it on and a GitHub Release exists; merges on `main` alone never raise the notice.

## Next

Phases 0 to 8 of the [migration plan](docs/migration-plan.md) are done;
the [decision records](docs/adr/README.md) say why each piece is as it
is. What is still missing comes in four tracks: the views and spreadsheet
gestures people miss, data in and out at any size, what an instance
administrator cannot yet do from Administration, and what a review of the
code found to tighten. Inside a table, the order is the priority; across
tracks, the order of work below decides.

### Order of work

A row moves up only when it unblocks another.

1. A UUID field type: 6.
2. Data in and out past 100,000 rows: 82, 83, with 47 (a job retried),
   which matters once jobs run longer.
3. Administration lot 3: 69, 22.
4. Keys before backups: 64, then lot 4 (17, 25). Row 51
   needs no code: a version tag runs the release workflow.

### Administration

An instance administrator should do everything from Administration, with
no command line and no access to the database: bring people in, choose
which bases each person reaches and with which role, see every base and
every outbound share, and keep the trails. Accounts, the security policy,
sources, and the trails are there; what is not comes in eight lots, in
this order, one pull request each (more when one would be too large to
read). Lot 8 is done on request only.

## Non-goals

- SDK, secrets CLI, and Helm in this tree
- AnyGridDB's own store on anything but PostgreSQL (ADR 0003). MySQL, MariaDB, SQL Server, and Oracle come in as external sources (ADRs 0006, 0024)
- A paid or enterprise build
- MinIO (abandoned upstream), or any non-OSI default
