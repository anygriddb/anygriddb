## Known limits

- A calendar reads the first 1,000 rows of the six weeks it shows; its days still count every row. A map shows the first 5,000 rows that have a place, and says so. A list nests the first 5,000 rows of its view, and says so; a row whose parent is not among them is drawn under no other. A grouped grid shows its first 2,000 groups.
- A base snapshot writes at most `EXPORT_MAX_ROWS` rows and reads at most `IMPORT_MAX_ROWS`, all tables together, and a base copied through one takes the smaller: a million each by default (ADR 0076). The direct download of a view, a field copied with its values, and an import that updates rows by key stop at 100,000 rows. A copied table keeps its rows' numbers and order, not their files. An import stops at the ceiling the operator sets (`IMPORT_MAX_ROWS`, 1,000,000 by default). An export job stops at the ceiling the operator sets (`EXPORT_MAX_ROWS`, 1,000,000 by default); it reads page after page by offset, so its last pages take longer. Export and snapshot files are kept for 24 hours.
- A chart reads at most 2,000 groups, a category with each of its series: ordered by value, it draws the largest of those.
- A failed or interrupted export or copy is retried by its author, from the tasks menu. An import is not: the rows it wrote before it stopped stay, and its author imports the file again.
- A field can require a value in AnyGridDB's own tables only (a client's database says itself what it requires), and not on a checkbox, a person, a file, or a link. Rows already empty when it becomes required stay so until that field is changed.
- A view saved while one of its fields is in the trash keeps that field's place and settings, but not its conditions inside a nested filter group, a colour rule, or a form field's condition.
- A base snapshot names people by email: a user cell keeps the people who are members of the new base. Roles given by groups stay behind.
- A workbook made a base brings its sheets' values: a formula comes as the value the file kept, and its formatting, charts, comments, merged cells, and the links between its sheets do not come (ADR 0078). Its fields take the types every row of their sheet fits, and can be converted afterwards.
- A collaborator with field or row rules finds in the row trash only the rows they deleted, named by their primary field when they may see it; on a client's table they have no row trash.
- A SAML provider that sends only transient or address NameIDs matches accounts by address: it must verify them. OIDC, and SAML with a persistent NameID, bind the account to the provider's subject.
- The map view shows the rows of its view over a plain background, or over the tiles of the server an administrator names (ADR 0068). Over tiles it pans and zooms; over the plain background it stays fitted to its rows.
- A synced table is as old as its last refresh, is read-only, stops at a million rows, and links to a table read live show empty.
- A locked client row is protected from AnyGridDB's writes only: a change another application makes is detected (within five minutes, seconds on a watched table) and told, not refused. Its seal covers every stored column, so a row put back still differs by its `updated_at`.
- On SQL Server a page is one query: a table with very many complex computed fields can exceed what SQL Server compiles, and AnyGridDB says so. There, MD5, SHA256, and SHA512 read texts of up to 100,000 characters, and JSON_EXTRACT reads a text value of up to 4,000.
- On Oracle an empty text is NULL, so a blank text and lists built from it read as nothing; `NUMBER` keeps no scale (`7.50` reads `7.5`); `DATE` reads as a day; regular expressions are refused, as on SQL Server. Only Oracle 23ai is tested; 19c is the floor (docs/sources.md).
- Regular expressions are a portable subset, written in the formula: `\d`, `\w`, and `\s` are ASCII, and back-references and lookbehinds are refused. SQL Server reads none before 2025, so there they are refused.
- JSON_EXTRACT needs PostgreSQL 16 or later, where a text that is not JSON can be told apart without failing the read. On MySQL it reads JSON numbers as doubles, and the field says so.
- A script in an automation reads and writes the rows of its own base, with its author's access, and calls public HTTPS addresses through the instance, ten times at most, one mebibyte an answer, redirects not followed (ADR 0101). A secret it sends is kept by its automation for one host, and is never shown again nor given to the script. A script is stopped after 10 seconds, at 64 MiB of memory, or after 100 reads and writes, the scripts of one run share a minute, and a number comes to it as the API gives it, as text. Scripts are off until an administrator allows them (ADR 0099).
- The opt-in release check stays silent until an administrator turns it on, and tells of published releases only: merges on `main` alone never raise the notice.
- Putting a value back reads the change trail (ADR 0089). A comment's earlier text, a role, a token, a secret, a journal of runs or deliveries, and the arrangement of the screen are not put back. A field whose type has changed is not put back from before the change. A file the store no longer has cannot come back with the cell. A value written in a client's database outside AnyGridDB is not here.

## Next

What is still missing comes in three tracks: what an instance
administrator cannot yet do from Administration, the applications and
languages around an instance, and the views and organisation people miss.
Inside a table, the order is the priority; across tracks, the order of
work below decides. Why each piece is as it is: the
[decision records](docs/adr/README.md).

### Order of work

A row moves up only when it unblocks another.

1. Applications and languages: 106 once decided; 105 once its languages
   are chosen.
2. Administration: 38 and 43 on request; 34 once decided.
3. Views and organisation: 8, 9, and 10, later.

## Non-goals

- SDK, secrets CLI, and Helm in this tree
- AnyGridDB's own store on anything but PostgreSQL (ADR 0003). MySQL, MariaDB, SQL Server, and Oracle come in as external sources (ADRs 0006, 0024)
- A paid or enterprise build
- MinIO (abandoned upstream), or any non-OSI default
