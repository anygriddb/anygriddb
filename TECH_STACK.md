# Tech stack

Audit date: **2026-11-14**. This page lists what the tree runs today. Why
each piece was chosen is in the [decision records](docs/adr/README.md);
what comes next is in the [roadmap](ROADMAP.md#next).

## Runtime

| Piece          | Choice    | Why                                                                        |
| -------------- | --------- | -------------------------------------------------------------------------- |
| Node.js        | 26        | LTS since October 2026, pinned by mise                                     |
| pnpm           | 11.28     | Workspace package manager; versions wait seven days before install         |
| Turborepo      | 2.11      | `dev`, `build`, `lint`, `typecheck`, `test`                                |
| TypeScript     | 6.0.3     | Newest release `typescript-eslint` can parse. 7.0 is published and blocked |
| PostgreSQL     | 18        | Default OLTP; 17 stacks move with `scripts/upgrade-postgres.sh`            |
| Files          | Disk      | A directory by default; any S3 service as an option (ADR 0010)             |
| RustFS         | 1.0.4     | Optional S3-compatible store (`compose.s3.yml`), Apache-2.0                |
| Docker Compose | `docker/` | One install path. One multi-stage image without compilers, as `node`       |
| API build      | esbuild   | One bundle with the workspace packages; migrations ship next to it         |

Packages resolve modules with `moduleResolution: Bundler`: they run through tsx, Vitest, esbuild, or Vite, never through `tsc` output.

The catalog goes through Kysely with camelCase names in TypeScript and snake_case in PostgreSQL; keys inside `jsonb` documents are left as they are. User tables never go through that mapping: the SQL that `packages/core` builds runs with `runStatement`. Arrays and plain objects written to the catalog are sent as JSON (the catalog has no array columns). After a migration, regenerate the types with `pnpm --filter @anygriddb/db db:types` against a freshly migrated database (`DATABASE_URL`); the integration test `db-types.integration.test.ts` fails when they lag.
